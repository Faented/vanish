# vanish — честное защищённое удаление (Rust, кроссплатформенный CLI)

vanish стирает файлы и каталоги так, чтобы восстановление форензикой было
невозможно, и **отказывается работать там, где не может дать гарантию** —
вместо того чтобы делать вид, что стёр. Отчёты не содержат исходных имён:
только `name_hash` (SHA-256) и хвосты `.vanish-v1-*`.

- **v1.0-linux** — готов (Linux-бэкенд, стратегия overwrite, отказо-политики).
- **v1.1-windows (M4)** и **v1.2-macos (M5)** — следующие этапы плана.
- Модель угроз: `docs/threat-model.md`; конвейер и политика: `docs/PLAN.md`;
  вердикты QA: `docs/qa/`.

---

## 1. Быстрый старт

```bash
# полная сборка: тесты + UPX-упаковка (если upx установлен) + манифест SHA256SUMS
bash scripts/build-release.sh

# проверить целостность (SHA-256 живого exe против манифеста):
dist/vanish --selfcheck            # rc=0 — бинарь не подменён

# затереть и удалить файл:
dist/vanish /path/secret.bin

# каталог целиком (файлы + поддеревья):
dist/vanish /path/stuff/

# посмотреть, ЧТО и КАК vanish намерен сделать (ничего не меняет):
dist/vanish --dry-run /path/secret.bin
```

⚠️ **Данные после vanish не восстановить ни одной утилитой** (photorec и
аналоги возвращают ноль — проверено на QA-полигоне). Программа не задаёт
вопросов подтверждения; сначала прогоняйте `--dry-run`, чтобы понять план,
а сама программа отказывается от опасных вещей (см. §5).

## 2. Установка и сборка с упаковкой

**Путь сборки — единственный штатный:**

```bash
# зависимости: rustup/cargo; опционально upx (упаковка ~ в 2.7 раза меньше бинарь)
sudo pacman -S rustup upx          # Arch/CachyOS
# (пакер можно не ставить: скрипт соберёт неупакованный бинарь и предупредит)

git clone <ваш-репозиторий> vanish
cd vanish
bash scripts/build-release.sh      # → dist/vanish + dist/SHA256SUMS
dist/vanish --selfcheck            # [ok] — бинарь целый
```

**Что делает скрипт (в этом порядке — это важно):**
1. `cargo build --release`;
2. `upx --best --lzma` на копию бинаря в `dist/` (если upx установлен);
3. SHA-256 **финального** файла → `dist/SHA256SUMS` (манифест считается после
   упаковки — иначе сверка была бы ложной).

**Артефакты сборки:**

| Файл | Смысл |
|---|---|
| `dist/vanish` | бинарь; после UPX ≈ 333 КиБ из 872 КиБ (в логе: `893888 → 333132, 37.27%`) |
| `dist/SHA256SUMS` | манифест вида `<sha256>  vanish` |

**Проверка целостности (три способа):**

```bash
dist/vanish --selfcheck                              # манифест ищется рядом с exe
dist/vanish --selfcheck /path/to/SHA256SUMS          # явный путь
VANISH_SHA256SUMS=/path/to/SHA256SUMS vanish --selfcheck
cd dist && sha256sum -c SHA256SUMS                   # стандартная утилита понимает формат
```

Коды выхода `--selfcheck`: **0** — бинарь целый; **1** — TAMPERED (хэш не
совпал — не используйте в защищённых задачах); **2** — манифест не найден
(укажите путь); **4** — ошибка выполнения.

## 3. Режимы программы

### wipe (по умолчанию: `vanish ЦЕЛЬ…`)

```bash
vanish file.bin                                   # 1 проход, паттерн random (NIST 800-88)
vanish --passes 3 --verify --pattern zero f.bin   # 3 прохода нулями + проверка каждого
vanish --pattern gutmann f.bin                    # 35-проходный Gutmann (медленно)
vanish --json /data/mystuff > report.json         # отчёт v1 (без plaintext-имён)
vanish --dry-run tree/                            # план: что будет стёрто и как
```
Полезные флаги wipe:
- `--no-rename` — не прятать имя под хвост `.vanish-v1-<hash>` перед unlink;
- `--accept-cow` — осознанно разрешить COW-ФС (Btrfs/ZFS); только если у вас нет снапшотов;
- `--wipe-all-hardlinks` — удалить ВСЕ жёсткие ссылки (без флага: отказ rc=3);
- `--xdev` — не переходить границы файловых систем при обходе дерева;
- `--no-trim` / `--trim` — отключить/включить деаллокацию (PUNCH_HOLE/FITRIM) после wipe.

### check — диагностика пути (read-only)

```bash
vanish check /path
```
Покажет: backend, тип ФС и её вердикт (например, «RAM-ФС: unlink достаточно»),
число жёстких ссылок, процесс-держатели (openers), swap-устройства.

### freespace — затирание свободного места

```bash
vanish freespace /data                  # весь свободный бюджет (95% доступного)
vanish freespace /data --size 1073741824   # не более 1 ГиБ
```
Перезаписывает страницы, освободившиеся ранее, чтобы «выцарапать» старые данные.

### device — блочное устройство (UNSAFE)

```bash
vanish device /dev/sdX --yes        # --yes обязателен: действие необратимо
```
SSD: `BLKSECDISCARD` (полное санитирование) → `BLKDISCARD` (быстрая деаллокация)
→ фоллбэк; HDD — последовательная перезапись устройства.

### recovery — дожимание хвостов

```bash
vanish recovery [путь…]             # дожимает незавершённые .vanish-v1-*
vanish --recovery-scan /path        # то же, флагом
```
После crash/kill посреди конвейера хвосты будут найдены и чисты.

### selfcheck

См. §2. Применяйте после доставки бинаря или при любых сомнениях в поставке.

## 4. Коды выхода

| Код | Значение |
|---|---|
| 0 | все указанные цели успешно затёрты |
| 1 | partial: что-то стёрто, что-то отвергнуто политикой |
| 2 | ошибка использования (аргументы; нет манифеста selfcheck) |
| 3 | отказ по политике (busy/cow_fs/hard_links…) — цель не тронута |
| 4 | внутренний сбой (verify/IO) — разберитесь и повторите |

## 5. Политики отказа (fail-closed) — это фича

| Отказ | Почему | Обход |
|---|---|---|
| `busy` (rc=3) | файл открыт другим процессом (скан /proc): перезапись не завершится честно | закройте держателя, повторите |
| `cow_fs` (rc=3) | Btrfs/ZFS: снапшот может хранить старые блоки | `--accept-cow` (осознанный) |
| `hard_links` (rc=3) | nlink>1: останется второе имя на тот же inode | `--wipe-all-hardlinks` |
| `ram_unlink` | tmpfs: данные только в RAM; unlink — достаточное удаление | честная стратегия (`bytes=0`) |
| `verify` (rc=4) | прочитанное не совпало с паттерном | не продолжать; проверьте носитель |

Тихих частичных затераний не существует и существовало не может: либо
гарантия, либо отказ с отчётом.

## 6. Отчёт vanish.report.v1 (приватность)

```json
{ "schema": "vanish.report.v1", "targets": [
    { "name_hash": "9e1fdb232f42…", "status": "ok",
      "bytes": 1048576, "warnings": [] }
] }
```
- имена файлов и абсолютные пути в отчёте отсутствуют; по умолчанию JSON
  можно складывать рядом с логами — он безопасен в форензическом смысле;
- вывод терминала показывает только хэши имён и итоги.

## 8. Ограничения v1.0 (честно)

- ext4 **с журналом**: имена могут осесть в журнале; vanish журнал не трогает
  (QA-полигон использует ext4 без журнала; будущее — `--wipe-ext4-journal`);
- device-wipe проверен на loop-носителе; на живом SSD прогонов пока не было;
- Windows/macOS-бэкенды — по плану (v1.1/v1.2), сейчас это честные заглушки.
